# Excalidraw 二次开发指南与最佳实践

## 1. 核心原则：寄生式开发 (Parasitic Development)

鉴于 Excalidraw 核心库 (`packages/excalidraw`) 代码的高度耦合性和复杂性（上帝类 `App.tsx`），在进行二次开发时，应遵循**“最小侵入”**原则。我们将 Excalidraw 视为一个**黑盒渲染引擎**，而非一个可以随意重构的代码库。

### 1.1 核心策略

1.  **黑盒对待**：尽量避免直接修改 `packages/excalidraw` 内部源码。任何对核心库的修改都会导致后续合并上游更新变得极其痛苦。
2.  **防腐层 (Anti-Corruption Layer)**：在业务代码与 Excalidraw 之间建立明确的边界。
3.  **插件化思维**：将所有新增功能视为“插件”，通过 Excalidraw 提供的公开 API (`excalidrawAPI`) 和 Props 插槽进行交互。

---

## 2. 架构设计模式

### 2.1 UI 扩展策略：劫持与注入

不要试图在 `App.tsx` 的 `render` 方法中硬编码你的业务组件。

*   **Props 插槽**：优先使用 Excalidraw 提供的原生插槽：
    *   `renderTopRightUI`: 顶部右侧工具栏扩展。
    *   `renderCustomStats`: 自定义统计面板。
    *   `renderFooter`: 底部扩展。
*   **React Portal 注入**：如果原生插槽无法满足布局需求（例如需要侧边栏、悬浮窗），使用 `React Portal` 将业务组件直接挂载到 Excalidraw 的 DOM 容器节点上，完全绕过 React 组件树的层级限制。

### 2.2 状态管理策略：双层状态分离

严禁将业务状态（Business State）混入 Excalidraw 的 `AppState`。

*   **Excalidraw AppState**：仅用于存储**纯绘图相关**的状态（如：缩放比例、滚动位置、当前选中的工具、选区颜色）。
*   **业务 Store (Jotai/Zustand)**：存储**应用级**状态（如：用户登录信息、文件列表、云端同步状态、AI 生成内容）。
*   **状态同步机制**：
    *   **监听**：通过 `excalidrawAPI.onChange` 监听画布变化，必要时同步到业务 Store。
    *   **注入**：通过 `excalidrawAPI.updateScene` 将业务数据的变化（如导入新图形）注入回画布。

### 2.3 功能扩展策略：插件化封装

将每个独立功能封装为独立的 React 组件/Hook，保持逻辑闭环。

**错误示范**：
在 `App.tsx` 中添加一个 `handleGenerateFlowchart` 方法，并在 Toolbar 中硬编码一个按钮调用它。

**正确示范 (Plugin Pattern)**：
1.  创建 `plugins/FlowchartGenerator/index.tsx`。
2.  组件内部通过 `useExcalidrawAPI` 获取控制权。
3.  组件内部管理自己的 UI（弹窗、按钮）和逻辑。
4.  在最外层容器中渲染该组件。

## 3. 常见场景解决方案

### 3.1 自定义工具栏/侧边栏
不要修改 `LayerUI.tsx`。
*   **方案**：创建一个绝对定位的 `div` 覆盖在 Excalidraw 画布之上（设置 `z-index` 高于 Canvas 但低于 Modal），在这个 `div` 中渲染你自己的侧边栏组件。
*   **交互**：通过 `excalidrawAPI` 控制画布的 `width/height` 或 `viewMode` 来配合侧边栏的展开/收起。

### 3.2 拦截与自定义事件
不要在 `App.tsx` 的 `onPointerDown` 中添加 `if-else`。
*   **方案**：在 Excalidraw 容器外层包裹一个 `div` 并捕获事件（Capture Phase），或者使用 `excalidrawAPI.onPointerDown` 钩子。
*   **注意**：如果需要阻止 Excalidraw 的默认行为，确保你的事件处理逻辑执行顺序正确。

### 3.3 数据持久化与协作
不要依赖 Excalidraw 内置的 `collab` 模块（它是为官方 Demo 设计的）。
*   **方案**：完全重写数据层。
*   **实现**：监听 `onChange` 获取 `elements` 和 `appState`，通过你自己的 WebSocket/HTTP 服务同步到后端。使用 CRDT (如 Yjs) 处理多端冲突，然后通过 `updateScene` 将合并后的数据推回画布。

## 4. AI 功能深度集成指南

### 4.1 核心 API 能力矩阵

针对你的 AI 功能需求，Excalidraw 提供了以下关键 API：

| 功能需求 | API 方法 | 能力说明 |
|---------|---------|---------|
| **精确创建元素** | `updateScene({ elements })` | 批量创建/更新元素，支持完整的元素属性控制 |
| **增量修改元素** | `mutateElement(element, updates)` | 高性能的单元素属性修改，自动触发重渲染 |
| **批量操作优化** | `applyDeltas(deltas)` | 使用增量更新，避免全量替换，性能最优 |
| **获取画布状态** | `getSceneElements()` | 获取当前所有非删除元素 |
| **语义分析基础** | `getSceneElementsIncludingDeleted()` | 获取完整元素历史，用于理解用户意图 |
| **撤销/重做集成** | `captureUpdate: CaptureUpdateAction` | AI 操作也能被撤销 |
| **事件监听** | `onChange(callback)` | 实时监听画布变化，用于 AI 上下文感知 |

### 4.2 AI 场景实现方案

#### 场景 1：AI 生成流程图（智能布局）

**需求**：用户输入文本描述，AI 生成结构化的流程图，并自动排版。

**实现策略**：
```typescript
// 1. AI 解析用户输入，生成逻辑结构
const flowchartData = await aiService.parseFlowchart(userInput);

// 2. 使用布局算法计算元素位置（Dagre/ELK）
const layoutedNodes = layoutEngine.layout(flowchartData);

// 3. 转换为 Excalidraw 元素
const excalidrawElements = layoutedNodes.map(node => ({
  type: "rectangle",
  id: nanoid(),
  x: node.x,
  y: node.y,
  width: node.width,
  height: node.height,
  // ... 其他属性
}));

// 4. 一次性注入画布（支持撤销）
excalidrawAPI.updateScene({
  elements: [...existingElements, ...excalidrawElements],
  captureUpdate: CaptureUpdateAction.IMMEDIATELY, // 可撤销
});
```

**关键点**：
- 布局计算在外部完成（使用 Dagre.js 或 ELK.js）。
- 使用 `updateScene` 批量创建，而非逐个 `mutateElement`（性能差）。
- 设置 `captureUpdate` 确保用户可以撤销 AI 生成的内容。

---

#### 场景 2：AI 智能调整现有元素（语义理解）

**需求**：用户选中几个元素，说"把这些对齐并均匀分布"，AI 自动调整。

**实现策略**：
```typescript
// 1. 获取当前选中的元素
const selectedElements = excalidrawAPI
  .getSceneElements()
  .filter(el => appState.selectedElementIds[el.id]);

// 2. AI 理解意图并计算新位置
const adjustedPositions = await aiService.alignAndDistribute(selectedElements);

// 3. 使用 applyDeltas 增量更新（最高效）
const deltas = adjustedPositions.map(({ id, x, y }) => ({
  id,
  updates: { x, y },
}));

excalidrawAPI.applyDeltas(deltas);
```

**为什么用 `applyDeltas` 而非 `updateScene`？**
- `updateScene` 会替换整个 `elements` 数组，触发全量 Diff。
- `applyDeltas` 只修改变化的属性，性能是前者的 10 倍以上（在大型画布中）。

---

#### 场景 3：AI 实时预览（边生成边展示）

**需求**：AI 生成复杂图表时，逐步展示生成过程（类似打字机效果）。

**实现策略**：
```typescript
async function* aiGenerateWithPreview(prompt: string) {
  const stream = await aiService.streamGenerate(prompt);
  
  for await (const chunk of stream) {
    // 每次 AI 返回一个新元素
    const newElement = convertToExcalidrawElement(chunk);
    
    // 立即添加到画布（不记录历史）
    excalidrawAPI.updateScene({
      elements: [...excalidrawAPI.getSceneElements(), newElement],
      captureUpdate: CaptureUpdateAction.NEVER, // 中间状态不可撤销
    });
    
    yield newElement;
  }
  
  // 生成完成后，记录一次历史快照
  excalidrawAPI.updateScene({
    elements: excalidrawAPI.getSceneElements(),
    captureUpdate: CaptureUpdateAction.IMMEDIATELY,
  });
}
```

**关键技巧**：
- 中间状态使用 `NEVER`，避免撤销栈被污染。
- 最终状态使用 `IMMEDIATELY`，用户可以一键撤销整个 AI 生成结果。

---

#### 场景 4：AI 理解元素关系（箭头绑定分析）

**需求**：AI 需要理解"这个箭头连接了哪两个框"，用于生成文档或优化布局。

**实现策略**：
```typescript
import { getContainerElement, getBoundTextElement } from "@excalidraw/element";

function analyzeElementRelationships(elements: ExcalidrawElement[]) {
  const elementsMap = arrayToMap(elements);
  const relationships = [];

  for (const element of elements) {
    if (isArrowElement(element)) {
      // 获取箭头的起点和终点绑定
      const startElement = element.startBinding 
        ? elementsMap.get(element.startBinding.elementId)
        : null;
      const endElement = element.endBinding
        ? elementsMap.get(element.endBinding.elementId)
        : null;
      
      relationships.push({
        type: "connection",
        from: startElement?.id,
        to: endElement?.id,
        arrow: element.id,
      });
    }
    
    // 分析文本绑定关系
    const boundText = getBoundTextElement(element, elementsMap);
    if (boundText) {
      relationships.push({
        type: "label",
        container: element.id,
        text: boundText.text,
      });
    }
  }
  
  return relationships;
}

// AI 使用这些关系生成流程图描述
const relationships = analyzeElementRelationships(
  excalidrawAPI.getSceneElements()
);
const description = await aiService.generateDescription(relationships);
```

### 4.3 性能优化策略

#### 批量操作的正确姿势

❌ **错误做法**（会导致卡顿）：
```typescript
// 每次调用都会触发重渲染
for (const element of aiGeneratedElements) {
  excalidrawAPI.updateScene({
    elements: [...excalidrawAPI.getSceneElements(), element],
  });
}
```

✅ **正确做法**：
```typescript
// 一次性批量添加
excalidrawAPI.updateScene({
  elements: [
    ...excalidrawAPI.getSceneElements(),
    ...aiGeneratedElements,
  ],
  captureUpdate: CaptureUpdateAction.IMMEDIATELY,
});
```

#### 使用 `onChange` 进行智能防抖

```typescript
import { debounce } from "lodash";

const debouncedAIAnalysis = debounce(async (elements) => {
  const suggestions = await aiService.analyzLayout(elements);
  updateAISuggestionPanel(suggestions);
}, 1000);

excalidrawAPI.onChange((elements, appState) => {
  // 用户每次修改后，延迟 1 秒再调用 AI 分析
  debouncedAIAnalysis(elements);
});
```

## 5. 总结

> **"驯服，而不是重写。"**

Excalidraw 虽然代码结构复杂，但其渲染性能和交互细节是世界级的。通过上述策略，我们可以享受它带来的极致绘图体验，同时保持业务代码的整洁和可维护性。

**关键要点**：
1. **黑盒思维**：不修改核心代码，只通过 API 交互。
2. **性能优先**：批量操作用 `updateScene`，增量更新用 `applyDeltas`。
3. **用户体验**：AI 操作也要支持撤销/重做。
4. **渐进增强**：从简单的 AI 辅助开始，逐步深化集成。

有了这些 API，你的 AI 功能可以做到：
- ✅ 精确控制每个元素的每个属性
- ✅ 理解元素间的语义关系（箭头绑定、文本标签）
- ✅ 高性能的批量操作和增量更新
- ✅ 与撤销/重做系统无缝集成
- ✅ 实时预览和流式生成

**你不需要重写 Excalidraw，它已经为你准备好了一切。**

## 6. 技术债管理

在实际开发中，有时为了快速验证功能或应对紧急需求，我们可能会暂时采用"侵入式"的实现方式（直接修改 `packages/excalidraw` 核心代码）。这是可以接受的，但必须：

1. **明确记录**：在 `doc/TECH_DEBT.md` 中记录所有技术债。
2. **设定触发条件**：明确什么情况下必须重构（如遇到 Git 冲突）。
3. **定期回顾**：每个迭代结束时检查技术债清单，评估是否需要偿还。

**当前已知技术债**：
- 🔴 语音输入功能需要迁移到外部（详见 `TECH_DEBT.md`）

**原则**：
- ✅ 功能优先，架构其次（先让功能跑起来）
- ✅ 但不能无限堆积债务（每个迭代至少解决一个高优先级债务）
- ✅ 新功能必须遵循本指南的架构原则（不再增加新债务）
